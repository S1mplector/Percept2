# Sidebar — Puppeteer Launcher

Live VNS scene snapshot panel that launches new Puppeteer work from the current cursor context and reopens registered animations directly.

Source: `editor/src/main/java/com/jvn/editor/ui/PuppeteerLauncherPanel.java`

---

## Overview

The Puppeteer Launcher sits between VNS authoring and the Puppeteer animation editor.

As the caret moves through a `.vns` file, the panel resolves a cumulative scene snapshot:

- current label
- active background
- visible characters
- declared character image/preset paths
- related inline or external timeline context

The panel is split conceptually into two halves:

- **Snapshot launch area** — create a new animation from the current cursor, label start, or scene start
- **Registered animations browser** — reopen, rename, delete, and cluster-manage saved `scripts/timelines/*.jes` files

- **Default side:** Right
- **Tab name:** Puppeteer Launcher
- **Updates:** automatically while a `.vns` tab is active

## Snapshot Section

The upper section reflects the current script position.

| Element | Description |
|---------|-------------|
| **Line indicator** | Current caret line number and trimmed source line |
| **Label** | Most recent `@label` / `label` before the caret |
| **Background** | Active background id |
| **Timeline** | Inline timeline body or referenced registered timeline, when relevant |
| **Visible Characters** | Resolved visible characters in `charId @ position [expression]` form |
| **Open Timeline** | Opens the related inline or external timeline source |
| **Jump To Issue** | Jumps to the first launcher-resolved script issue |
| **Launch @ Cursor** | New animation from the exact current snapshot |
| **Launch @ Label Start** | New animation from the current label start |
| **Launch @ Scene Start** | New animation from the latest scene/background start point |

The snapshot launch buttons now open directly instead of routing through an extra chooser dialog.

## Registered Animations

The lower half is a browser for saved timelines under `scripts/timelines/`.

Each timeline is displayed as a compact card showing:

- timeline name
- quick stats
- DSL preview lines
- cluster/folder grouping
- current snapshot relevance/highlighting where applicable

Available per-card actions:

- **Open**
- **Rename**
- **Delete**

Clusters are derived from subdirectories under `scripts/timelines/`, so teams can organize animations into buckets such as:

- `characters/`
- `camera/`
- `intro/`
- `chapter_02/`

Renaming can also move a timeline between clusters by changing its relative path.

---

## Scene Snapshot Resolution

The launcher performs a lightweight VNS pass from line `1` through the caret. It recognizes:

- labels
- background declarations and background changes
- `@charimg`
- `@charlayer`
- `@charpreset`
- `[show]` / `[hide]`
- external character show/hide/move/expr commands
- inline timeline blocks
- external registered timeline references

This gives Puppeteer enough context to reconstruct the visible scene without building the full runtime scenario object first.

---

## Layered Character Support

The launcher understands layered character declarations, not just flat `@charimg` paths.

That means snapshot previews and Puppeteer scene construction can resolve:

- declared layered rigs
- preset-backed expressions
- correct composite image sources for layered characters

This matters for projects where visible expressions are assembled from multiple declared layers instead of a single sprite file.

---

## Empty or Timeline-Light Cards

If a registered timeline file has little or no body content, the card can still display useful context by falling back to the current launcher snapshot instead of only showing a dead “timeline block is empty” message.

Likewise, opening a registered animation now backfills missing scene entities from the available snapshot context so reopening saved work does not drop its visible targets.

---

## Typical Workflow

1. Open a `.vns` file
2. Move the caret to the story beat you want to animate
3. Review the snapshot in the upper half
4. Click **Launch @ Cursor** for new work, or pick a saved card below to reopen an existing animation
5. Animate in Puppeteer
6. Register/export the resulting timeline back into `scripts/timelines/`
